## ფაქტობრივი შემოწმება

* ექვსივე ჩანაწერი ხელახლა წაკითხულია ავტორიზებულ REST პასუხში `draft=true` პარამეტრით: `_status: draft`, `publishedAt: null`.
* წყაროსა და CMS-ის ტექსტური ბლოკები სრულად ემთხვევა: N01/N02/N05 — თითოეული 25; E01 — 18; E13 — 14; F01 — 20 ბლოკი.
* სათაურები, Slug-ები, SEO სათაურები/აღწერები და რეალური კატეგორიების ID-ები შემოწმებულია.
* Preview ექვსივე მასალაზე გაიხსნა. წინასახედის სათაურები და ტექსტები სრულად ემთხვევა წყაროს.
* Preview-ის რეჟიმი გამოირთო. ამის შემდეგ F01-ის მისამართმა აჩვენა 404 და ტექსტი აღარ გამოჩნდა.
* Posts-ის სიაში ექვსივე ახალი სათაური და Slug ჩანს. მანამდე არსებული ცარიელი ჩანაწერი, ID 1, შენარჩუნებულია.

## არსებული CMS-ის გამოყენება

მასალები ჩაიტვირთა Admin-ის არსებული რედაქტორით. ავტომატურმა შენახვამ Draft ვერსიები შექმნა; მათი გადამოწმება უნდა მოხდეს `draft=true`-ით, რადგან `draft=false` შეიძლება საბაზისო დოკუმენტს აბრუნებდეს. ეს Draft-ის დაკარგვას არ ნიშნავს.

Rich Text რედაქტორმა HTML-ის ჩასმა არსებულ Lexical სტრუქტურად გარდაქმნა. ამ ჩატვირთვის შედეგი არ ნიშნავს, რომ პაკეტის ყველა მზა REST სხეულის bulk-იმპორტი გამოცდილია. დანარჩენი მასალების ჩატვირთვამდე დარჩენილი ურთიერთობებისა და მოქმედი სერიული ფორმატის შემოწმება საჭიროა. მთლიანი პაკეტის `cms/posts.remaining.drafts.json` შეიცავს 25 დარჩენილ სხეულს და უკვე შექმნილ ექვს Slug-ს გამორიცხავს.

პასუხისმგებელი CMS ავტორი არ მინიჭებულა: authors არჩევითია, ჟურნალის ავტორები კი ბიბლიოგრაფიაშია შენარჩუნებული. კლინიკური/სარედაქციო დამტკიცება ამ ჩატვირთვით არ იგულისხმება. N08 კვლავ შეჩერებულია საბოლოო ვერსიის დაზუსტებამდე.

## სამუშაოს ფარგლები

ნებართვა ექვსი ახალი Production Draft-ისა და საჭირო კატეგორიებისთვის მომხმარებელმა ცალკე გასცა. ადმინისტრატორის შექმნა მომხმარებელმა არსებული `admin:create` ბრძანებით დაასრულა; შემდეგ ავტორიზებული CMS წვდომა დადასტურდა. პაროლი და სესიის საიდუმლო მონაცემები ანგარიშში არ ინახება.

ამ სამუშაოში არ შეცვლილა აპლიკაციის კოდი, main, მთავარი გვერდის კონტენტი, Railway-ის გარემოს ცვლადები ან ინფრასტრუქტურა. Clinical Library-ის ჩანაწერებს არ შევხებივართ. PR არ გაერთიანებულა.

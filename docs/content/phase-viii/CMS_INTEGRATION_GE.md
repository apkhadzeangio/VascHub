## კატეგორიები

ტიპის კატეგორიებია „სამეცნიერო სიახლეები“, „საერთაშორისო ღონისძიებები“, „პროფესიული განვითარება“. კლინიკური თემებია PAD/CLTI, კიდურის მწვავე იშემია, კაროტიდული დაავადება, აორტის დაავადებები, სისხლძარღვოვანი ინფექცია, ვენური დაავადებები, ჰემოდიალიზის მიდგომა, სისხლძარღვოვანი ტრავმა, მეზენტერიული/თირკმლის სისხლძარღვები და გაიდლაინები/კონსენსუსი.

სრული სახელები და slug-ები მოცემულია `cms/categories.proposed.json`-ში. ჯერ მოიძებნოს არსებული შესაბამისი კატეგორია; ახალი შეიქმნას მხოლოდ თუ მართლა არ არსებობს. Clinical Library-ის taxonomy ცალკეა და არ გადაიხარისხოს. მიმდინარე ეტაპზე კატეგორიები არ შექმნილა. `category_id_map.required.json`-ში ID-ები განზრახ null-ია.

## უსაფრთხო გადატანა არსებული საშუალებებით

ამ ეტაპის ფარგლებში შესრულებულია კონტენტის მომზადება და ფაილების გენერაცია. Production-ში არც Draft ჩანაწერი შექმნილა: მონახაზიც ბაზის ცვლილებაა და ამ დავალების შეზღუდვით დაუშვებელია.

შემდეგ, როდესაც კონტენტის ჩატვირთვის ეტაპი ცალკე იქნება ავტორიზებული:

1. გადაამოწმეთ მოქმედი სქემა და ადმინისტრატორის უსაფრთხო წვდომა. ამ სამუშაოს შედეგად ნანახი საწყისი მომხმარებლის ფორმა არ არის ანგარიშის შექმნის ნებართვა.
2. Categories-ში იპოვეთ ზუსტი შესაბამისობები; მიღებული რეალური ID-ები ჩაწერეთ სამუშაო ასლში. კვლევის ავტორები CMS მომხმარებლებად არ შექმნათ.
3. მცირე პირველი პარტიისთვის გამოიყენეთ Admin → Posts → Create New. გადაიტანეთ სათაური, slug, აღწერა და ტექსტი; აირჩიეთ კატეგორია და პასუხისმგებელი ადგილობრივი რედაქტორი; გამოიყენეთ **Save Draft**.
4. ალტერნატივაა არსებული REST API, ახალი Route-ის გარეშე: ავტორიზებულ იზოლირებულ სატესტო გარემოში ერთი ჩანაწერის შექმნა `POST /api/posts?draft=true`-ით, სხეულში `_status: draft`. JSON მასივი ერთ მოთხოვნად ავტომატურ bulk-იმპორტს არ ნიშნავს: სტანდარტული Create ოპერაცია ერთ დოკუმენტს ქმნის. მზა ფაილები წარმოადგენენ ცალკეული მოთხოვნების სხეულებს.
5. პაკეტის `posts.news.drafts.json` მოიცავს 13 სიახლეს; N08 გამოტანილია ცალკე შესაჩერებელ ფაილში. `posts.events.drafts.json` მოიცავს 13 ინფორმაციულ ანონსს. `posts.opportunities.drafts.json` შეიცავს 5 ჩანაწერს; დახურული F06 და დაუდასტურებელი ახალი მიღების F07 ცალკე საცნობარო ფაილშია. F08 იმავე ENHANCE EVAR კურსს აღწერს, რასაც E12: გამოიყენეთ E12-ის ერთი კანონიკური ანონსი და არ გამოაქვეყნოთ დუბლიკატი. ყველა მონახაზში categories ცარიელია და გამოქვეყნების დრომდე რეალური მიბმა სჭირდება.
6. Preview-ში შეამოწმეთ ქართული ტექსტი, ბმულები, წყაროს თარიღი და მნიშვნელოვანი რიცხვების მნიშვნელი. API ფორმატის ფაილები არ არის ცოცხალ Payload გარემოში გამოცდილი — ამის დასადასტურებლად ამ ეტაპზე ნებადართული სატესტო გარემო არ არსებობდა. JSON-ის სტრუქტურული შემოწმება შესრულდა ლოკალურად.
7. კონკრეტული მასალის სარედაქციო დამტკიცებისა და მიმდინარე ვადების ხელახალი შემოწმების შემდეგ შესაძლებელია გამოქვეყნება. მოცემული კალენდარი გეგმაა და არც jobs-ს და არც ავტომატიზაციას არ ქმნის.

მზა Admin CSV/JSON იმპორტი მიმდინარე აპში კოდის დამატების გარეშე ვერ დადასტურდა. ოფიციალური Import/Export plugin ცალკე დაყენებასა და კონფიგურაციას საჭიროებს; ამიტომ აქ არ დამატებულა. 13 სიახლის პირველი პარტიისთვის ხელით Draft-ები ყველაზე მცირე ტექნიკური ჩარევაა.

## მთავარი გვერდის კონტენტის არჩევანი

საწყისი ორი სიახლის კანდიდატებია N01 და N02. ისინი newsPosts-ში მხოლოდ გამოქვეყნების შემდეგ შეიძლება შეირჩეს. საწყისი ორი ღონისძიების კანდიდატებია E01 LINC და E13 ონლაინ CLTI Masterclass; მეორე განსაკუთრებით ხელმისაწვდომია მოგზაურობის გარეშე. `homepage-events.proposed.json` მხოლოდ ჩანაწერების წინადადებაა და არა Pages/home-ის PATCH სხეული.

ღონისძიების მიმდინარე მოდელში დასრულების თარიღის ველი არ არსებობს. დიაპაზონი ჩაწერეთ მოკლე სათაურში; date-ში შეინახეთ დაწყების კალენდარული დღე Admin-ის თარიღის არჩევით. ოფიციალური დაწყების საათი არ გამოიგონოთ. არსებული ფილტრი დაწყების თარიღის გასვლის შემდეგ ღონისძიებას მალავს, მაშინაც კი, თუ მრავალდღიანი შეხვედრა ჯერ გრძელდება.

Pages/home-ის მთლიანი ჩანაწერის ძველი JSON-ით ჩანაცვლება დაუშვებელია: სხვა პროცესი შეიძლება პარალელურად ცვლიდეს Clinical Library-სთან დაკავშირებულ ინფორმაციას. შემდეგ ეტაპზე რედაქტორმა უნდა შეცვალოს მხოლოდ newsPosts/events და შეამოწმოს ბოლო ვერსია; არც layout და არც Library-ის კავშირები არ გადაიწეროს.

* ღონისძიების სათაურში დარჩეს თარიღის დიაპაზონი; ადგილსა და ოფიციალურ გვერდს უკვე არსებული ველები მოემსახურება.
* შესაძლებლობის პირველი აბზაცი ასახელებდეს ნამდვილ სტატუსს: აქტიური მიღება, მუდმივი პროგრამა, დახურული ციკლი ან მხოლოდ ცენტრის მოძიების გზა. ფერი სტატუსის ერთადერთი განმასხვავებელი არ უნდა იყოს.
* მობილურზე ინფორმაციის პრიორიტეტი: სათაური → თარიღი/სტატუსი → პრაქტიკული სარგებელი → მოთხოვნა → წყარო. ამ ეტაპზე ეს კონტენტის წერის რეკომენდაციაა; განლაგება არ შეცვლილა.
* არსებული placeholder-ის გამო ფოტო სავალდებულო არ არის. არ გამოყენებულა ჟურნალი/კონგრესის დაცული ფოტო ან პაციენტად აღსაქმელი გენერირებული კლინიკური ილუსტრაცია.

## დარჩენილი საკითხები

N08 საჭიროებს საბოლოო ვერსიის დაზუსტებას. რამდენიმე ხელმისაწვდომი მიმოხილვა მხოლოდ აბსტრაქტით შემოიფარგლა — ეს თითოეული სტატიის source_access-ში და ტექსტში მითითებულია. PAUSE-ის ბილეთების მონაცემი წინააღმდეგობრივია; სამი სხვა კურსი შევსებულია. F03-ის საწყისი თარიღი უკვე გასულია; F06 დახურულია, F07-ის ახალი მიღება დაუდასტურებელია. ამ საკითხებზე წერილი ან განაცხადი ამ სამუშაოს ფარგლებში არ გაგზავნილა.

შემდეგი იმპლემენტაცია: პირველ რიგში ადმინისტრაციული წვდომის საკითხის მოგვარება არსებული პროექტის უსაფრთხო ინსტრუქციით, შემდეგ 2–3 დამტკიცებული ახალი Draft-ის ხელით გადატანა და Preview. ახალი CMS, მონაცემთა ბაზა, ფასიანი რესურსი ან აპლიკაციის კოდი საჭირო არ არის.

## CMS-ის საჯარო პასუხებით დაზუსტება — 29.10.2026

არსებული Categories REST API-ის პირდაპირ წაკითხულ პასუხში `docs: []` და `totalDocs: 0` დაფიქსირდა. Posts-ის არაავტორიზებულ პასუხშიც `totalDocs: 0` იყო; Posts-ის read წვდომა გამოქვეყნებული დოკუმენტებითაა შემოსაზღვრული, ამიტომ ეს დახურული Draft-ების ინვენტარიზაცია არ არის. ზუსტი პასუხები ინახება `cms/public-readonly-audit.json`-ში. რეალური კატეგორიების ID-ები ვერ მიება; ID-ების რუკა განზრახ უცვლელად null დარჩა. კატეგორიები არ შექმნილა.

სქემაში `categories` და `authors` ველებს `required: true` არ აქვთ. მათი შევსება ამ პაკეტის სარედაქციო ორგანიზების ამოცანაა და არა Draft-ის ტექნიკურად სავალდებულო პირობა. პასუხისმგებელი რედაქტორის კლინიკური განხილვა რეკომენდებულია; ამ განხილვის ჩატარება ან კონკრეტული მომხმარებლის არჩევა ამ სამუშაოში არ დასტურდება.

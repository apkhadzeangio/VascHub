# VascHub-ის მთავარი გვერდი

მთავარი გვერდი ეფუძნება [Figma v1.1 დიზაინს](design/homepage-brief.md) და იყენებს
სტარტერის Button/Input/Card, Pages/Posts/Categories, Header/Footer და ავტორიზაციას.
შენარჩუნებულია არსებული გვერდები, სტატიების რედაქტორი და ადმინისტრატორის დაცვა.
საჯარო პროფესიული ანგარიშები ამ ეტაპში არ არის დამატებული.

## კონტენტის რედაქტირება

1. არსებული ადმინისტრატორით შედით `/admin`-ში.
2. Pages-ში გახსენით ან შექმენით გვერდი, რომლის slug არის `home`.
3. „მთავარი გვერდი“ ტაბში შეცვალეთ წარწერა, სათაური, წარდგენა და კლინიკური თემები.
4. სურვილისამებრ აირჩიეთ მაქსიმუმ სამი რესურსი, ერთი სასწავლო სტატია და ორი სიახლე
   არსებული გამოქვეყნებული Posts-იდან. რესურსების ცარიელი არჩევანი აჩვენებს სამ
   ბოლო განახლებულ გამოქვეყნებულ სტატიას. სიახლესა და სასწავლო მასალას არჩევანი სჭირდება.
5. დაამატეთ მაქსიმუმ ორი რეალური ღონისძიების მოკლე ცნობა: დასახელება, ბმული,
   სურვილისამებრ თარიღი და ადგილი. გასული თარიღის ჩანაწერები მთავარზე აღარ ჩანს.
6. გამოაქვეყნეთ გვერდი. მხოლოდ Draft-ში შენახული ცვლილებები საჯაროდ არ გამოჩნდება.

მთავარი გვერდი ხელმისაწვდომია `/` და `/home` მისამართებზე. ჩვეულებრივი გვერდების
Hero/Content ბლოკები შენარჩუნებულია; `home` იყენებს მთავარის სპეციალურ განლაგებას.
მთავარის გვერდის არარსებობისას მუშაობს ქართული შესავალი, თემები და გააზრებული
ცარიელი მდგომარეობები. გამოგონილი სამედიცინო კონტენტი ან ღონისძიებები არ იტვირთება.

Header-ისა და Footer-ის არსებული globals ინარჩუნებს რედაქტირებად სანავიგაციო ბმულებს.
ცარიელი Header აჩვენებს დიზაინის ექვს ძირითად მიმართულებას. პროფესიული ქსელის,
წევრობისა და პირადი სივრცის ღილაკები ხსნის ინფორმაციას მიუწვდომლობის შესახებ;
ისინი `/admin`-ზე არ გადადის. აკადემიის ბლოკი ამ ეტაპზე გამოქვეყნებული სასწავლო
სტატიის მიმანიშნებელია; კურსების გავლა და რეგისტრაცია დამატებული არ არის.

## ძიება და საჯარო წვდომა

`/search?q=...` არის რეალური GET ძიება. იძებნება გამოქვეყნებული Posts-ის სათაურები,
SEO სათაური/აღწერა და შესაბამისი კატეგორიები. მუშაობს Enter-ით გაგზავნა, ცარიელი
შედეგი და გვერდებად დაყოფა. ტექსტი არ აცხადებს ჯერ არარსებული კურსების ძიებას.

საჯარო მოთხოვნები იყენებს `overrideAccess: false`, `draft: false` და გამოქვეყნების
ფილტრს. რედაქტორის მიერ არჩეული სასწავლო/რესურსის სტატია გამოქვეყნების გაუქმებისას
აღარ გამოჩნდება მთავარზე. არსებული Search plugin შენარჩუნებულია CMS-ში;
მისი ინდექსის პირდაპირი საჯარო კითხვა გამორთულია. საჯარო გვერდი ეყრდნობა Posts-ის
აქტუალურ მონაცემებს, რათა მოძველებულმა ინდექსმა Draft-ის მეტამონაცემები არ გამოიტანოს.

## დიზაინის განხორციელება

- Noto Sans Georgian ლოკალურად იტვირთება `src/fonts/`-დან; OFL ლიცენზია თან ერთვის.
- Figma-ის VascHub ნიშანი ინახება `public/vaschub-mark.svg`-ში; ხატულები — Lucide.
- მთავარი და სანავიგაციო ჩარჩო იყენებს დიზაინის ღია ფერთა ტოკენებს.
  ძველი კონტენტის ბლოკების თემის სტილები შენარჩუნებულია.
- მობილურის მიზნობრივი სიგანე 390 px-ია, კონტენტი — 350 px. შემოწმებულია 768 და
  1440 px-იც. შემცირებული 234 px დიზაინის ასლი CSS საზომად გამოყენებული არ არის.
- მენიუ იყენებს ბრაუზერის native `dialog`-ს: focus trap, Escape, დახურვის ღილაკი,
  დამწყებ კონტროლზე ფოკუსის დაბრუნება და გახსნისას body scroll-ის შეჩერება.

დიზაინისგან აუცილებელი სხვაობებია რეალური საძიებო მოცულობის ტექსტი, გამოქვეყნების
მდგომარეობის შესაბამისი ცარიელი ბლოკები, სტატიების განახლების თარიღები და მიუწვდომელი
მიმართულებების განმარტება. დემო იარლიყები რეალურ მონაცემებზე არ გადმოტანილა.

## გაშვება და შემოწმება

გამოიყენეთ ძირითადი README-ის `.env` და Docker/ლოკალური ინსტრუქციები:

```bash
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm dev
```

ახალი მიგრაცია ამატებს მხოლოდ Pages/homepage-ის ველებს, მათ version-ებსა და
დაკავშირებულ ცხრილებს. არსებული Pages/Posts არ იშლება და არ გადაახარისხდება.
`push: false` შენარჩუნებულია; ახალი ფილიალის გაშვებამდე მიგრაცია აუცილებელია.

```bash
pnpm typecheck
pnpm lint
pnpm test:int
pnpm build
E2E_SERVER_COMMAND='pnpm start' pnpm test:e2e
```

Integration/E2E ტესტები გაუშვით მხოლოდ ცალკე `_test` ან `-test` ბაზაში.
Homepage fixture დამატებით ამოწმებს ბაზის სახელწოდებას. სადემონსტრაციო მასალა
იქმნება მხოლოდ ტესტებში და იშლება დასრულებისას; production seed არ დამატებულა.

GitHub CI-ში browser previews ინახება `homepage-browser-previews` artifact-ში:
ცარიელი მობილური და კონტენტიანი გვერდი 390/768/1440 px-ზე. რეალური CMS რედაქტირება,
ძიება, Draft-ის დამალვა, მენიუს ფოკუსი და არსებული admin regression ტესტებით მოწმდება.

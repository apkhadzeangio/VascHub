## ადმინისტრატორის ინსტრუქცია

1. შედით არსებულ `/admin`-ში არსებული ადმინისტრაციული ანგარიშით.
2. ჯგუფში „პროფესიული ქსელი“ გახსენით „სპეციალისტები“ ან „სისხლძარღვთა ცენტრები“.
3. შეავსეთ მხოლოდ დადასტურებული საჯარო ინფორმაცია. ქალაქისა და მიმართულების
   ერთი და იმავე მნიშვნელობისთვის გამოიყენეთ თანმიმდევრული მართლწერა.
4. ფოტო სურვილის შემთხვევაში აირჩიეთ არსებული Media-დან; კონტაქტი ან ცენტრთან
   კავშირი სავალდებულო არ არის. შეიყვანეთ მხოლოდ გასაჯაროებისთვის განკუთვნილი კონტაქტები.
5. `Save Draft` ინახავს მონახაზს; `Publish` / `Publish changes` აქვეყნებს.
   უკვე გამოქვეყნებული ჩანაწერის ახალი Draft საჯარო ვერსიას არ ცვლის.
6. Unpublish მალავს პროფილს საჯარო გვერდებიდან, ფილტრებიდან და კავშირებიდან.
   Draft ცენტრი შეიძლება ადმინისტრატორმა მიაბას, მაგრამ საჯაროდ მხოლოდ გამოქვეყნების შემდეგ გამოჩნდება.

Users კვლავ ადმინისტრაციული ანგარიშებია. სპეციალისტის პროფილი Users-ს არ ქმნის.
არ დამატებულა საჯარო რეგისტრაცია, წევრობა, რეიტინგები, დაჯავშნა, გადახდები, ჩატი
ან შეტყობინებების გაგზავნა. გამოქვეყნება კვალიფიკაციის, ვერიფიკაციის ან ცენტრის
აკრედიტაციის დამადასტურებელ ნიშნად არ არის წარმოდგენილი.

## საჯარო წვდომა

საჯარო query-ები აშკარად იყენებს `overrideAccess: false`, `user: null`, `draft: false`,
`_status = published`-ს და ველების projection-ს. ადმინისტრატორის cookies ან preview
რეჟიმი ამ მოთხოვნებში არ გადადის. ცენტრები და Media დამატებით იკითხება სტუმრის
წვდომით. არარსებული/მიუწვდომელი ფოტო ხატულით იცვლება; დაკარგული კავშირი არ რენდერდება.
Payload-ის Media URL-ის projection შეიცავს `filename`-საც, რადგან URL ამ ველიდან გენერირდება.

ანონიმური native API-ის relationship `afterRead` შლის არასაჯარო centre ID-ებსაც.
სტუმრის `centres equals/in` query/count ფილტრები მხოლოდ გამოქვეყნებულ ID-ებზე
სრულდება. დაკავშირებული ცენტრის შიდა ველებით WHERE/sort და relationship distinct
სტუმრისთვის 400-ით იზღუდება, რათა დამალული კავშირები count/join მოთხოვნით ვერ გამოიცნოს.
ადმინისტრატორის native CMS API Draft-ს კანონიერად ხედავს. CRUD და version history
არსებულ `authenticated` წესს იყენებს; საერთო access helpers უცვლელია.

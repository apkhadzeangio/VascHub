# ინტეგრაციის ეტაპისთვის დარჩენილი საკითხები

ქვემოთ მოცემული ფაილები Agent B-ის უფლებამოსილებას სცდება და არ შეცვლილა.
შესწორებული საერთო public reader-ის ექსპორტი კვლავ `(collection, slug)` არის;
იგი ID-ით ძიებად არ გადაკეთებულა.

## 1. Redirect-ის PostgreSQL reference ID

ფაილი: `src/components/PayloadRedirects/index.tsx`.

კოდი არაპოპულატებულ reference-ს მხოლოდ `typeof value === 'string'` შემთხვევაში
ამუშავებს. PostgreSQL-ის `number` ID else ტოტში გადადის და შეიძლება ცარიელი Slug-ის
ბმული შეიქმნას. სტრიქონული ID-ის ტოტიც `getCachedDocument(collection, id)`-ს იძახებს,
ხოლო ეს helper Slug-ით ეძებს. პრობლემები წყაროს დონეზე დადასტურდა; რეალური HTTP
redirect სცენარი Agent B-ს არ გაუშვია.

ინტეგრაციის აგენტმა დაამუშაოს numeric/string ID და populatებული ობიექტი, მოძებნოს
reference ID-ით საჯარო წვდომის დაცვით და missing/draft სამიზნეზე არ შექმნას
`/undefined` ან ცარიელი გადამისამართება. დაიცვას არსებული Slug-reader კონტრაქტი.
დაამატოს ორივე კოლექციის redirect-ის მოქმედი და დაკარგული reference-ის ტესტები.

## 2. SEO მისამართები

ფაილები: `src/plugins/index.ts`, `src/utilities/generateMeta.ts`.

SEO plugin-ის `generateURL` ორივე კოლექციისთვის `${url}/${doc.slug}`-ს აბრუნებს:
Post-ის რეალური გზა კი `/posts/<slug>`-ია, home-ისა — `/`.
`generateMeta`-ში `openGraph.url` მხოლოდ array Slug-ს ამუშავებს; მიმდინარე სქემაში
Slug სტრიქონია და ამიტომ დეტალურ გვერდზეც `/` მიიღება. ეს წყაროს დონეზე მიგნებაა.

ინტეგრაციის აგენტმა გამოიყენოს კოლექციის შესაბამისი გზა და დაამატოს ტესტები
home/Page/Post-ის URL-ებზე, მათ შორის ქართულ Slug-ზე. ეს ფაილები B-ს არ შეუცვლია.

## 3. რეალური Next request-ის შემოწმება

ინტეგრაციის სატესტო სერვერზე შეამოწმეთ Slug-ის შეცვლის შემდეგ ძველი/ახალი მისამართი,
Header/Footer-ის populatებული ბმულები, გამოქვეყნებიდან მოხსნა, საჯარო სიები და
Preview enable/exit. B-ის hook ტესტები ადასტურებს invalidation გამოძახებებს, ხოლო
Payload ტესტები — წვდომისა და ვერსიების ქცევას. HTTP cache/cookie სცენარი ცალკეა.

## 4. ელფოსტის დამოკიდებულება

Payload-ის კონფიგურაციაში email adapter არ არის. ლოკალურმა გაშვებამაც console
adapter-ის გაფრთხილება აჩვენა. Password reset-ის წერილის რეალური მიწოდება მოქმედად
არ უნდა გამოცხადდეს. პროვაიდერისა და კონფიგურაციის არჩევა ცალკე დარჩენილი საკითხია;
ამ სამუშაოში წერილი არ გაგზავნილა და რესურსი არ შექმნილა.

# კლინიკური ბიბლიოთეკა v0.1

ბიბლიოთეკა ხელმისაწვდომია `/library`-ზე. რესურსები PostgreSQL-დან იძებნება;
ძიების ინდექსის ასლები და სადემონსტრაციო კლინიკური კონტენტი არ გამოიყენება.

## ადმინისტრირება

1. შედით არსებულ `/admin` პანელში.
2. „კლინიკური ბიბლიოთეკა → კლინიკური რესურსები“-ში შექმენით ჩანაწერი.
3. შეავსეთ სათაური, აღწერა, ტიპი, ავტორი ან გამომცემელი, წელი, ენა და კატეგორიები.
4. მიუთითეთ გადამოწმებული ოფიციალური HTTPS წყარო, DOI ან ნებადართული PDF.
5. შეინახეთ მონახაზი ან გამოაქვეყნეთ. მხოლოდ გამოქვეყნებული ჩანაწერი გამოჩნდება
   საჯარო გვერდებზე, ძიებასა და sitemap-ში. გამოქვეყნების გაუქმება მას დაუყოვნებლივ მალავს.

`LibraryResources` (`library-resources`) დამოუკიდებელი Collection-ია: წყაროს
წელი, ვერსია, DOI, ენა და ლიცენზირებული დოკუმენტი სტატიების მოდელისგან განსხვავდება.
გამოიყენება არსებული `Categories`, `Users`, Button/Input/Label/Card, Lucide,
ქართული შრიფტი და Figma v1.1-ის არსებული CSS tokens. `Pages`/`Posts`/`Media`
ჩანაწერები და ადმინისტრატორების ავტორიზაცია შენარჩუნებულია.

კატეგორიები იმართება არსებული `Categories` განყოფილებიდან. მიგრაცია ამატებს
შვიდ საწყის თემას მხოლოდ მაშინ, თუ იგივე slug ან სათაური არ არსებობს:
აორტა, კაროტიდული არტერიები, პერიფერიული არტერიული დაავადება, ვენური პათოლოგიები,
დიალიზის სისხლძარღვოვანი წვდომა, სისხლძარღვთა ტრავმა და სხვა.

„წყაროს განახლების თარიღი“ კლინიკური დოკუმენტის თარიღია;
„ჩანაწერის განახლება“ CMS-ის ავტომატური `updatedAt`-ია.
SEO სათაურისა და აღწერის არშევსებისას გამოიყენება რესურსის სათაური და აღწერა.
DOI მოწმდება ფორმატით; წყაროს ნამდვილობა და სამეცნიერო ხარისხი რედაქტორმა უნდა გადაამოწმოს.

## PDF ფაილები

„ბიბლიოთეკის PDF ფაილები“-ში ატვირთვა შესაძლებელია არსებული ადმინისტრატორით.
საჭიროა განთავსების უფლების დადასტურება და ლიცენზიის/ნებართვის საფუძვლის აღწერა.
ეს ინფორმაცია და ფაილის CMS ჩანაწერი ანონიმურად მიუწვდომელია.

- დაშვებულია მხოლოდ `.pdf`, `application/pdf`, PDF header და Payload-ის
  PDF integrity შემოწმების გავლით. მაქსიმალური ზომაა **20 MiB**.
- ფაილების URL-იდან სერვერზე ავტომატური ჩამოტვირთვა გამორთულია.
- ფაილები ინახება `LIBRARY_FILES_DIR`-ში, ნაგულისხმევად `private/library-files`;
  `public/`-ში ამ გზის მოთავსებას აპი უარყოფს. არსებული საჯარო `Media` არ გამოიყენება.
- `/library/[slug]/pdf` ყოველი მოთხოვნისას ამოწმებს გამოქვეყნებულ რესურსს,
  ფაილის არსებობასა და ნებართვას. პასუხია `attachment`, `nosniff`, `sandbox`,
  `no-store` და `noindex`; უფლებების გაუქმებისას ჩამოტვირთვა წყდება და ბმული ქრება.
- უფლებების გასაუქმებლად ფაილის ჩანაწერში მოხსენით შესაბამისი მონიშვნა.
  რესურსის მონახაზად დაბრუნება ან წაშლაც წყვეტს ამ რესურსიდან ჩამოტვირთვას.
- ავთენტიფიცირებულ ადმინისტრატორს შეუძლია PDF-ის ნახვა არსებული Payload ფაილის
  მარშრუტით. საჯარო ჩამოტვირთვა მხოლოდ გამოქვეყნებული რესურსის გავლით მუშაობს.

ატვირთვის შემოწმება ანტივირუსს ან PDF-ის აქტიური შიგთავსის სრულ სანიტიზაციას არ წარმოადგენს.
არ ატვირთოთ პაციენტის მონაცემები ან დაუდასტურებელი მესამე პირის ფაილები.
უკვე გადმოწერილი ფაილის ასლების გაუქმება შეუძლებელია.

## საჯარო ინტერფეისი

`/library` აერთიანებს ტექსტურ ძიებას, კატეგორიას, რესურსის ტიპს, ენას,
გამოცემის წელსა და დალაგებას. ერთ გვერდზე მაქსიმუმ 12 რესურსია;
გვერდების ბმულები ფილტრებს ინარჩუნებს. ცარიელ შედეგებს ახლავს გასუფთავების მოქმედება.
ძიება მოიცავს სათაურს, აღწერას, ავტორს, საკვანძო სიტყვებს, DOI-სა და კატეგორიის სათაურს.
გამოიყენება Payload-ის პარამეტრიზებული PostgreSQL მოთხოვნები და სტუმრის წვდომა.
მონახაზი საჯარო გვერდებზე არც ადმინისტრატორის სესიით ჩანს; რედაქტირება ხდება CMS-ში.

მთავარ გვერდზე ბიბლიოთეკის სამი ბოლო განახლებული რესურსი და სრული ბიბლიოთეკის
ბმულია. არსებული სტატიების ძიება `/search`-ზე შენარჩუნებულია; მთავარი გვერდის
კლინიკური თემები `/library`-ში გადადის. ნავიგაციის ძველი `/#resources`
ბიბლიოთეკის ბმული ახალი მისამართით იხსნება, CMS-ის ჩანაწერის გადაწერის გარეშე.

დეტალურ გვერდს აქვს canonical და Open Graph მეტამონაცემები. ფილტრიანი
სიები `noindex, follow`-ით აღინიშნება. `/library-sitemap.xml` მოიცავს
მხოლოდ მიმდინარე გამოქვეყნებულ რესურსებს და არ ინახავს ძველ სტატუსებს cache-ში.

## გაშვება და მონაცემების შენარჩუნება

არსებული `.env`-ის დამატებითი პარამეტრია `LIBRARY_FILES_DIR`.
Compose იყენებს `/app/private/library-files` გზასა და `library_files` მუდმივ volume-ს.
მონაცემთა ბაზის სარეზერვო ასლთან ერთად შეინახეთ როგორც `media_data`, ისე ეს volume.
სქემის ავტომატური push გამორთულია; გაშვებამდე შეასრულეთ `pnpm db:migrate`.
მიგრაცია `20261028_212007_clinical_library` ამატებს ახალ ცხრილებს,
ვერსიებს, ინდექსებსა და Payload lock-ის კავშირებს. არსებული ჩანაწერები არ იშლება.

მხოლოდ სატესტო ბაზაზე მიგრაციის rollback/reapply შესამოწმებლად:

```sh
pnpm payload run scripts/check-library-migration.ts
```

სკრიპტი ითხოვს `_test`/`-test` ბაზას და ცარიელ ბიბლიოთეკას. ამოწმებს არსებული
სტატიისა და კატეგორიის კავშირის შენარჩუნებას. Rollback შლის ბიბლიოთეკის ახალ
ცხრილებსა და მათ კონტენტს; საერთო კატეგორიებს ტოვებს. Production-ზე rollback-მდე
აუცილებელია ჩვეულებრივი სარეზერვო ასლისა და მონაცემების გადატანის გეგმა.

## შემოწმება

```sh
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm typecheck
pnpm lint
pnpm test:int
pnpm payload run scripts/check-library-migration.ts
pnpm build
pnpm exec playwright install --with-deps chromium
E2E_SERVER_COMMAND="pnpm start" pnpm test:e2e
```

სატესტო მასალები ცალსახად მონიშნულია, იწერება მხოლოდ გამოყოფილ სატესტო ბაზაში
და ტესტის შემდეგ იშლება. Production seed არ დამატებულა. წევრობა, კურსები,
ექიმების რეესტრი და სხვა დიდი მოდულები ამ ვერსიაში არ შედის.
